# Сетевой кооп: состояние и что дальше

Полная схема в `docs/ARCHITECTURE.md` («Сетевой кооп»), таблицы и правила в `docs/LEADERBOARD.md`. Здесь короткая сводка для продолжения работы.

## Сделано

- Симуляция на двоих (`src/core/sim.js`, числа в `src/data/coop.js`): общий опыт и уровень, карточки по очереди, но у каждого свой пул (свои изгнанные и reroll/skip/banish), свой DPS и урон на итогах, сундук тому, кто подобрал, гроб вместо смерти (оживает по таймеру, быстрее рядом с напарником), игроки не расходятся дальше экрана, спавн ×1.4, HP врагов ×1.15, скрыто опыт ×1.25, по 4 слота на игрока.
- Герои: мечница (Blade Arc) и магесса (Storm Chain, `HEROES.mage`). Выбор героя в соло (меню: Play → герой → сложность, последний выбор в настройке `hero`) и в лобби (каждый выбирает сам, сообщение `hero`, хост передаёт `heroes` в `start`). Один герой на двоих взять нельзя: в лобби герой напарника занят, при одновременном выборе уступает гость, сим тоже раздаёт разных (`src/core/heroes.js`). Спрайт магессы: PixelLab по `assets/raw/mage.png`, в меню она слева отражённой, симметрично мечнице.
- Lockstep (`src/core/lockstep.js`): ввод с задержкой 6 тиков (100 мс; свой герой рисуется с предсказанием), команды экранов, хеш состояния раз в секунду. Фиксированный шаг 60 Гц в `Game.js` (и в соло); в коопе время ожидания копится и догоняется, опередивший напарника притормаживает часы.
- Соединение (`src/services/net.js`): WebRTC DataChannel, offer/answer через Firestore `rooms/<код>`, STUN Google, без TURN.
- Лобби (`src/scenes/Lobby.js`), вид Co-op в меню, HUD как в соло (только свой игрок), итоги с парой ников, таблица коопа `fury_scores_coop` с полем `ip` и дедупом по IP, вкладки Solo / Co-op.
- Тесты: `tests/unit/coop.test.js`, `tests/unit/lockstep.test.js`, балансный бот на двоих (`players: 2`), `tests/smoke/coop.spec.js` (два окна, настоящий WebRTC, сигналинг через localStorage).

## Нужно руками

- Опубликовать `firestore.rules` в консоли Firebase (коллекции `rooms`, `fury_scores_coop`, поле `ip`). Без этого лобби не создаётся.
- Портрет магессы (`mage_portrait`, 48×48) пока заглушка, в игре он нигде не показывается.

## Известные ограничения

- Нет TURN: за симметричным NAT (мобильные операторы, CGNAT) или при заблокированном UDP соединение не пройдёт (лобби скажет «Could not connect»). Диагностика: консоль браузера (F12), фильтр `fury-net` — кандидаты ICE у обоих (без `srflx` нет внешнего адреса, STUN недоступен), состояния ICE, выбранный путь, причина обрыва.
- Версии: в `hello` лобби отпечаток игры (`simFingerprint`: хеш данных и короткого забега); разные версии — старт закрыт, обоим перезагрузить страницу. Он же шестью hex-символами в правом нижнем углу меню (`v ee3c62`): у двоих должен совпадать.
- Рассинхрон: в консоль `[fury-net] DESYNC` с тиком и полями состояния, которые разошлись (клиенты обмениваются своими `hashParts`).
- Рассинхрон только фиксируется (`__game.debug().desynced`), игра не чинит состояние. Chrome с Chrome сходится.
- Экран с содержимым сундука в коопе закрывается сам через 2.5 с, сим напарника не ждёт.
- Повтор забега в коопе только через новое лобби. Если напарник ушёл из лобби, код уже не работает: Cancel и новое лобби.
- Свёрнутая вкладка останавливает цикл Phaser: ввод не уходит, напарник через `NET.dropAfter` (20 с) видит потерю связи.
- Рассинхрон показывается строкой в HUD (`coop.desync`), игра продолжается, счёт у двоих может разойтись; причина в консоли (см. выше).
- Пинг больше ~100 мс в одну сторону (задержка ввода) даёт частые остановки: адаптивной задержки нет.

## Проверка экрана выбора на многих героях

Тестовые герои не попадают в репозиторий: скрипт съёмки в браузере дописывает в `HEROES` записи со спрайтами и именами врагов и боссов (до N героев) и снимает выбор героя в соло и лобби (два окна, сигналинг через `__furySignal`). Скрипт лежал в рабочей папке сессии (`heroes-n.mjs`), его суть: `import('/src/data/heroes.js')` в странице, `HEROES[id] = { ...HEROES.heroine, sprite: ENEMIES[x].sprite, startWeapon }`, `en['hero.' + id + '.name'] = ...`, затем Menu → Play.
